# MASTER BUILD PROMPT

## Generic Enterprise AI Knowledge Platform — Build From Scratch

You are acting as a **senior enterprise software architect, AI/RAG architect, backend engineer, frontend engineer, DevOps engineer, security engineer, and QA engineer**.

Your task is to build a **production-grade, generic Enterprise AI Knowledge Platform from complete scratch**.

This is NOT a Glatt-specific application.

The product must be designed so that:

> **Today it can be deployed at Glatt. Tomorrow the exact same product can be deployed for another company without changing the core architecture or source code.**

The system must support multiple organizations/tenants, multiple users, configurable knowledge bases, configurable document types, multiple AI providers, enterprise RAG, permissions, auditability, and future agentic AI capabilities.

---

# 1. MOST IMPORTANT PRINCIPLE

Build this as a **reusable enterprise AI product**, not as a project-specific application.

DO NOT hardcode:

- Glatt
- Glatt-specific document types
- Glatt-specific departments
- Glatt-specific workflows
- Glatt-specific users
- Glatt-specific IP addresses
- Glatt-specific model names
- Glatt-specific database names
- Glatt-specific storage paths

# 10. PERMISSION-AWARE RAG

Unauthorized information must NEVER reach the LLM.

Correct flow:

```text
User
 ↓
Authenticate
 ↓
Authorize
 ↓
Determine accessible Knowledge Bases
 ↓
Determine accessible Documents
 ↓
Retrieve only authorized chunks
 ↓
Rerank
 ↓
Build context
 ↓
LLM
```

Incorrect architecture:

```text
Retrieve everything
 ↓
Give everything to LLM
 ↓
Filter response
```

NEVER implement the second approach.

Document ingestion must be idempotent.

If the same file is uploaded twice, use checksums/hashes to detect duplicates where appropriate.

Avoid:

```text
duplicate chunks
duplicate vectors

```

Jobs should be safe to retry.
